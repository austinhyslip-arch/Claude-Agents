# Sales Ops Agent (austin@chanty.com)

A daily job that keeps your sales systems in sync automatically:

1. Reads Gmail threads from the last 24 hours for austin@chanty.com
2. Uses Claude to figure out what stage each conversation is in
3. Updates matching contact records in Attio
4. Checks Google Calendar to confirm meetings mentioned in email actually got booked, and flags ones that didn't
5. Schedules follow-up tasks based on last contact date (3-4 days out for initial outreach, longer gaps for later stages)

No human approval step. It runs, it writes to your systems, it logs what it did.

## Before you turn this on

The `stage` status field already exists on People in Attio, with all 11 pipeline values this agent expects (Not Contacted through LOST-Closed) — confirmed directly against the workspace.

Still missing: a `last_contacted_at` field on People. The agent writes to it after every classified thread and there's no MCP tool that can create Attio attributes, so add it by hand: **Attio > Settings > Data Model > People > Add attribute**, type `Date`, slug `last_contacted_at`.

Until that field exists, the agent will run in dry-run mode and log what it *would* update instead of writing.

## Setup

### 1. Install dependencies
```bash
pip install -r requirements.txt
```

### 2. Google OAuth (Gmail + Calendar)
You need a Google Cloud project with Gmail API and Calendar API enabled, and OAuth credentials for austin@chanty.com.

1. Go to console.cloud.google.com, create/select a project
2. Enable "Gmail API" and "Google Calendar API"
3. Create OAuth 2.0 credentials (Desktop app type)
4. Download the JSON, save as `config/google_credentials.json`
5. Run `python src/auth_setup.py` once, locally, to complete the OAuth flow and generate `config/google_token.json`. This only needs to happen once; the token refreshes itself after that.

### 3. Attio API key
Attio > Settings > API & Webhooks > create a key with read/write access to People, Companies, and Lists. Put it in `.env`.

### 4. Anthropic API key
Used to classify email conversations into pipeline stages. Get one from console.anthropic.com. Put it in `.env`.

### 5. Environment file
Copy `.env.example` to `.env` and fill in the values.

## Running it

**One-time test run (dry run, no writes):**
```bash
python src/main.py --dry-run
```

**Live run:**
```bash
python src/main.py
```

## Deploying it to run daily on its own

This repo ships with `.github/workflows/sales-ops-agent.yml`, which runs the agent daily at 11:00 UTC (6am America/Chicago) via GitHub Actions, plus a manual "Run workflow" button with a dry-run toggle. To turn it on:

1. In this repo, go to **Settings > Secrets and variables > Actions** and add:
   - `ATTIO_API_KEY`
   - `ANTHROPIC_API_KEY`
   - `GOOGLE_CREDENTIALS_JSON` — the full contents of `config/google_credentials.json`
   - `GOOGLE_TOKEN_JSON` — the full contents of `config/google_token.json`, generated by running `python src/auth_setup.py` locally once (see step 2 below)
2. The workflow writes those two Google secrets to files at the start of each run and refreshes the access token in-memory using the stored refresh token — it doesn't need to persist anything back.
3. **Important:** if your Google Cloud OAuth consent screen is in "Testing" publishing status, Google expires the refresh token after 7 days and the daily run will start failing silently. Before relying on this, set the consent screen to "In production" (external) or "Internal" (if austin@chanty.com is on a Google Workspace you administer) in the Cloud Console.

If you'd rather run it somewhere you control instead:

**Cron on a machine you control**
```bash
crontab -e
# add this line to run at 6am every day
0 6 * * * cd /path/to/sales-ops-agent && /path/to/python src/main.py >> logs/agent.log 2>&1
```

**A small cloud function (AWS Lambda / GCP Cloud Function) on a scheduled trigger**
More setup, but no machine to keep running. Worth it once you trust the logic and want it fully hands-off from any repo or laptop.

## What it actually writes

- Attio: updates the `stage` status field, and a `last_contacted_at` date field, on matching People records (matched by email address)
- Google Calendar: creates follow-up hold events on your calendar (does not send invites to contacts, just blocks your own time), titled `Follow up: {contact name}`
- Local log file (`logs/agent.log`): every decision it made and why, so you can audit what happened each day

## Follow-up cadence logic

Defined in `config/cadence_rules.yaml`. Default:
- Initial outreach, no reply yet: follow up 3-4 days after last outbound email
- Prospect replied, no meeting booked: follow up 2 days after their reply
- Meeting held, no next step scheduled: follow up 1 day after the meeting
- Proposal sent: follow up 5 days after send
- No activity in 21+ days: flagged as stale, not auto-followed-up (goes in the log for you to review manually)

Edit the YAML file to change any of this without touching code.
